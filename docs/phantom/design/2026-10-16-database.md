# phantom-db — 경량 데이터베이스 콘솔 설계

- 날짜: 2026-10-16
- 대상: Phantom IDEA (intellij-community `idea/262.10968.63` 포크, 이 저장소)
- 사용자 프로필: Kotlin + Spring Boot + JPA + Gradle 백엔드 개발자
- 설계 방식: **clean-room**. Ultimate의 동작·비용 설명(`Intellij-rea/reversed/` 노트)과 Ultimate 플러그인 디스크립터의 기능 이름, 커뮤니티 API, 공개 스펙(JDBC, 각 DBMS 문서)만 근거로 쓴다. 디컴파일 코드(`reversed/source/`)는 열지 않았다. 라이선스·인증 코드는 다루지 않는다.

표기
- **[검증]**: 이 저장소에서 경로·클래스·EP 선언을 직접 확인했다.
- **[가정]**: 공개 지식이나 설계 판단이며 아직 확인하지 않았다.
- **[측정]**: `reversed/` 노트에 기록된 Ultimate 실측값이다 (주로 `03-decompiled/2026-10-16-ult-database.md`, `02-runtime/2026-10-16-startup-jfr.md`).

## 0. 결정 요약

| 선택지 | 판단 |
|---|---|
| (a) 마켓플레이스의 무료/오픈소스 플러그인을 쓴다 | 후보는 **Database Navigator**(DBN) 하나다. 무료 플러그인으로 존재한다는 점은 확신한다 [가정: 공개 지식]. 다만 262 빌드와 호환되는지, 시작 비용이 얼마인지, 자체 SQL 언어가 어떤 언어 ID를 쓰는지는 **unknown**이다. DBN은 Oracle 중심으로 출발했고 기능 범위가 넓어서, "1–3 방언만 지연 로드"라는 목표와 맞는지 측정 전에는 알 수 없다. 그 밖의 무료 플러그인은 이름을 확신할 수 없어 적지 않는다. 외부 도구(DBeaver Community 같은 독립 앱)는 IDE 메모리를 전혀 쓰지 않는 대안이다. |
| (b) 최소 자체 콘솔을 만든다 | **권장.** 무거운 부품 세 가지가 이미 커뮤니티에 있고 기본 번들돼 있다. 결과 그리드(`grid/`, `intellij.grid.core.plugin`), Maven 아티팩트 다운로드(`JarRepositoryManager`), SQL TextMate 문법이다 [검증]. 그래서 남는 작업은 데이터 소스 모델, JDBC 실행, 가벼운 SQL 렉서, 스키마 트리다. MVP는 약 16일로 본다. |

정리하면 이렇다. **v0.1은 자체 콘솔로 간다. DBN은 "자체 콘솔이 준비되기 전 임시 대안"으로 두고, 설치해 쓰려면 먼저 §5.3의 방법으로 비용을 측정한다.**

## 1. 목표와 범위

### 1.1 사용자가 매일 하는 일 (근거)

사용자 프로젝트 `~/orca/workspaces/prototype-reservation-system`에서 확인했다 [검증, 파일 grep].
- 운영/테스트 DB는 **MySQL**이다 (`mysql-connector`, `flyway-mysql`, `testcontainers-mysql`).
- 로컬 프로파일은 **H2**다 (`persistence/datasource/local.yaml`의 `org.hibernate.dialect.H2Dialect`). 드라이버는 P6Spy로 감싸져 있다.
- 마이그레이션은 **Flyway**다 (`infrastructure-module/src/main/resources/db/migration/V1_*.sql`).
- QueryDSL(kapt), Redis(Redisson)도 쓴다.

여기서 나오는 일상 작업은 다섯 가지다. 로컬/스테이지 MySQL에 붙어서 테이블과 컬럼을 확인한다. `SELECT`로 데이터를 본다. 마이그레이션 SQL 파일을 읽고 쓰면서 하이라이트를 받는다. 가끔 `UPDATE`/`DELETE`를 실행한다. 엔티티와 스키마가 맞는지 눈으로 대조한다.

### 1.2 MVP (v0.1)

1. **데이터 소스 관리**: MySQL, PostgreSQL, H2 세 가지. URL, 사용자, 비밀번호, 드라이버, 읽기 전용 플래그를 관리한다. 비밀번호는 `PasswordSafe`에 저장한다.
2. **드라이버 확보**: 두 가지 경로를 둔다. (1) Maven Central에서 내려받는다(`JarRepositoryManager`). (2) **프로젝트 Gradle classpath에 이미 있는 드라이버 jar를 그대로 쓴다.** 사용자 프로젝트에는 `mysql-connector-j`와 `h2`가 이미 있으므로 네트워크가 필요 없다.
3. **SQL 파일 타입과 하이라이트**: `.sql` 파일과 콘솔에 키워드, 문자열, 주석, 숫자, 식별자, 백틱/큰따옴표 식별자 하이라이트와 괄호 매칭을 제공한다. Flyway 마이그레이션 파일도 같은 하이라이트를 받는다.
4. **SQL 콘솔**: 데이터 소스마다 콘솔 하나를 둔다. `Ctrl+Enter`는 캐럿이 있는 문장이나 선택 영역을 실행한다. 결과는 **커뮤니티 그리드**로 보여 준다. 기본 500행을 가져오고 "더 가져오기"를 제공한다. update count와 오류는 콘솔 아래 로그 패널에 남긴다. 실행 취소(`Statement.cancel`)와 타임아웃을 지원한다.
5. **스키마 트리**: Database 툴 윈도우에 데이터 소스 → 스키마(catalog) → 테이블/뷰 → 컬럼·인덱스·FK 계층을 보여 준다. **노드를 펼칠 때만** `DatabaseMetaData`를 조회한다. 더블클릭하면 `SELECT * FROM t` 콘솔을 연다.
6. **완성 (최소)**: 키워드, 그리고 이미 펼쳐서 캐시된 테이블/컬럼 이름을 완성한다. 해석(resolve)과 검사(inspection)는 하지 않는다.
7. **안전장치**: 읽기 전용 데이터 소스에서는 DML/DDL 실행 전에 확인한다. `UPDATE`/`DELETE`에 `WHERE`가 없으면 경고한다(렉서 토큰 수준 판단).

### 1.3 v0.2 이후

- v0.2
  - Kotlin/Java 문자열에 SQL 주입: `@Query(nativeQuery = true)`, `JdbcTemplate.query*`, `@Language("SQL")`. 주입된 SQL에도 하이라이트를 준다.
  - Spring Boot 설정(`application*.yml|properties`의 `spring.datasource.*`)에서 데이터 소스를 **가져오는 액션**. 자동 감지 시작 활동은 만들지 않는다.
  - 결과 편집: 그리드 셀 수정 → `UPDATE` 미리보기 → 커밋 (`GridMutator`).
  - CSV/JSON/INSERT 내보내기 (커뮤니티 `grid/csv`, `ExtractorsHelper` EP 확인 필요).
  - 수동 트랜잭션 모드(auto-commit 끄기, Commit/Rollback 버튼).
  - 실행 계획: `EXPLAIN` 결과를 그리드에 그대로 보여 준다.
- v0.3 이후
  - 스키마 스냅샷을 `platform/sqlite`에 저장해서 재시작 직후 오프라인 완성을 제공한다.
  - 원격 JDBC 실행 프로세스 옵션(작은 `-Xmx`, 유휴 시 종료).
  - SSH 터널(`intellij.platform.ssh.plugin`이 기본 번들 목록에 있다 [검증: `ModuleSetPlugins.kt`]).
  - Flyway 인식(`flyway_schema_history` 보기, 다음 버전 파일 생성).
  - phantom-jpa와 연동해 엔티티 ↔ 테이블 컬럼 불일치를 표시한다(작은 API 모듈을 통해, §3.7).

### 1.4 명시적 비목표

- SQL 방언 60개. MySQL, PostgreSQL, H2(+ANSI 기본값) 외의 방언은 만들지 않는다.
- 완전한 SQL 파서와 PSI 해석(컬럼 resolve, 타입 추론, 수십 개 검사).
- 스키마 비교/diff, DDL 생성기, ER 다이어그램, 데이터 import 마법사, 데이터베이스 리팩터링.
- 루틴/프로시저 디버거, 사용자·권한 편집기, 세션 모니터.
- NoSQL(Mongo, Redis, Cassandra), 클라우드 데이터 소스 제공자, AI/MCP 연동.
- Settings Sync로 데이터 소스 동기화.
- Ultimate 설정 파일(`dataSources.xml`) 형식 호환. 독자 형식을 쓴다.

## 2. Ultimate 대비 경량화 원칙

Ultimate Database Tools의 측정된 비용 [측정]과, 이 설계가 그 비용을 어떻게 피하는지를 짝지었다.

| Ultimate에서 측정된 비용 | 원인 | phantom-db의 대응 |
|---|---|---|
| 콘텐츠 모듈 81개 중 `required` 78개, 그중 **SQL 방언 60개가 전부 required**. 방언 jar가 76 MB, 코드의 약 55%. 런타임 3,777 클래스, 로더 54개, metaspace 18.7 MB | 방언마다 `ParserDefinition`, 코드 스타일, 토큰 타입을 등록 | 콘텐츠 모듈은 required 3개(`sql`, `core`, `ui`)와 v0.2 optional 2개뿐이다. 방언은 **언어나 모듈이 아니라 하나의 렉서 안의 `SqlDialect` 플래그 enum**이다(MySQL 백틱·`#` 주석, PostgreSQL `$$`·`::`, H2/ANSI). 목표치는 데이터 소스 0개일 때 적재 클래스 < 150개, 사용 중일 때 < 1,000개다 |
| 데이터 소스·모델·이력 로드가 시작 4.9–5.8 s 구간에 걸림. postStartupActivity 4개가 프로젝트마다 **영구 코루틴**으로 남음 | 시작 활동에서 서비스를 eager로 깨우고, 구독자로 남김 | **시작 활동 0개.** 데이터 소스 저장소는 `PersistentStateComponent`라서 처음 읽힐 때만 역직렬화된다. 툴 윈도우를 열거나, 콘솔을 열거나, `.sql` 완성이 처음 호출될 때가 그 시점이다. 영구 collector는 만들지 않는다 |
| 드라이버 아티팩트 목록 763개를 XStream으로 파싱(약 170 ms), 원격 갱신 체크 | 앱 서비스 초기화 때 카탈로그 전체를 읽음 | 카탈로그는 플러그인 리소스의 **3–5개 항목짜리 JSON**이다. 드라이버 대화상자를 열 때만 읽는다. 원격 목록 갱신은 없고, 버전 목록은 사용자가 요청할 때 `JarRepositoryManager.getAvailableVersions`로 받는다 |
| 연결마다 `RemoteJdbcServer` 자식 JVM, 기본값으로 **IDE의 `-Xmx2048m`을 물려받음** | 격리를 위한 별도 프로세스 | v0.1은 **IDE 프로세스 안에서 드라이버별 격리 클래스 로더**로 실행한다. 행 수 상한(기본 500, 최대 10,000), `fetchSize`, 쿼리 타임아웃, 유휴 10분 후 연결 닫기를 둔다. 자식 JVM은 v0.3 옵션이고, 그때도 기본 `-Xmx256m`이다 (§6 리스크 R1) |
| 인트로스펙션 모델 XML을 프로젝트 열 때 통째로 읽음. 큰 스키마면 힙 수십 MB [측정 + 추론] | 데이터 소스 단위 단일 모델 | 메타데이터는 **트리 노드 단위로 지연 조회**하고, 메모리 캐시만 둔다(소프트 참조 + 데이터 소스별 상한). 디스크 스냅샷은 v0.3에서 `platform/sqlite`에 객체 단위로 저장한다 |
| `DatabaseIntrospectionScheduleManager`가 활성 데이터 소스마다 주기 갱신 스케줄러를 만듦 | 백그라운드 재인트로스펙션 | 주기 갱신이 없다. 사용자가 Refresh를 누를 때, 그리고 콘솔에서 DDL을 실행한 뒤 해당 스키마 노드 하나만 무효화한다 |
| 감지기(`dataSourceDetector`)가 smart mode 이후 프로젝트 설정을 스캔하고 알림을 띄움 | backgroundPostStartupActivity | 자동 스캔이 없다. v0.2의 "Spring 설정에서 가져오기"는 **사용자가 실행하는 액션**이다 |
| Settings Sync가 `options/dataSources.xml`을 동기화 | 앱 수준 저장 | 데이터 소스는 **프로젝트 수준**(`.idea/phantomDataSources.xml`)에 저장한다. 앱 수준 저장은 없다. 비밀번호는 파일에 쓰지 않는다 |
| Hibernate, `javaee-persistence-impl`이 DB 플러그인에 최상위 의존 → JPA를 쓰면 DB 플러그인을 끌 수 없음 | 역방향 결합 | **phantom-db로 들어오는 하드 의존을 금지한다.** 다른 phantom 플러그인은 optional 콘텐츠 모듈로만 연결한다 (§3.7) |
| grid-plugin `DataLoaderManager$Associations.contains`가 모든 파일의 `isMyFileType`에서 모니터 경합 7건, 713 ms [측정, startup-jfr] | 파일마다 판정기 호출 + 락 | SQL 파일 타입은 **확장자로만 등록**한다(`extensions="sql"`). `FileTypeIdentifiableByVirtualFile`을 쓰지 않는다. Ultimate의 `grid-plugin`(데이터 파일 로더)은 쓰지 않고, 커뮤니티 `grid-core-plugin`만 쓴다 |
| 활성화 조건 없음 | 의존성만 맞으면 로드 | Database 툴 윈도우는 `ToolWindowFactory.isApplicableAsync`로 다음 중 하나일 때만 노출한다: 프로젝트에 데이터 소스가 이미 있거나, 프로젝트 라이브러리에 JDBC 드라이버(mysql/postgresql/h2/mariadb)가 있거나, 사용자가 액션으로 처음 연다. 판정은 백그라운드에서 라이브러리 이름만 본다 |

공통 규칙
- **EDT 금지**: JDBC 호출, 메타데이터 조회, 드라이버 로딩, 파일 I/O는 전부 `Dispatchers.IO`에서 한다. EDT는 결과를 그리드 모델에 넣는 일만 한다.
- **서비스는 전부 lazy**(`@Service` + light service). 이른 초기화 플래그(`preload`)는 쓰지 않는다.
- **인덱스 0개.** `FileBasedIndex`나 stub 인덱스를 등록하지 않는다. `.sql` 파일 안 완성에는 콘솔 캐시만 쓴다.
- **프로젝트 전체 무효화 금지.** 캐시 키는 `(dataSourceId, catalog, schema, objectName)`이다. DDL 하나에는 그 스키마 노드 하나만 무효화한다.

## 3. 아키텍처

### 3.1 모듈 레이아웃

커뮤니티 플러그인 구조(`plugins/textmate/plugin/.../plugin.xml`이 `<content>`로 모듈을 묶는 방식)를 따른다 [검증].

```
plugins/phantom-db/
├── plugin/                         # intellij.phantom.db.plugin (디스크립터 전용)
│   └── resources/META-INF/plugin.xml
├── sql/                            # intellij.phantom.db.sql        loading="required"
│   └── src/com/phantom/db/sql/     # Language, FileType, Lexer, ParserDefinition(평평한 PSI),
│                                   # SyntaxHighlighter, BraceMatcher, Commenter, keyword completion
├── core/                           # intellij.phantom.db.core       loading="required"
│   └── src/com/phantom/db/core/    # DataSource 모델·저장, DriverCatalog, DriverResolver,
│                                   # ConnectionManager, QueryExecutor, MetadataCache
├── ui/                             # intellij.phantom.db.ui         loading="required"
│   └── src/com/phantom/db/ui/      # ToolWindow, 스키마 트리, 데이터 소스 대화상자, 콘솔, 그리드 연결
├── injection/                      # intellij.phantom.db.injection  (v0.2, optional)
│   └── ...                         # IntelliLang + Kotlin/Java 주입 설정
├── spring/                         # intellij.phantom.db.spring     (v0.2, optional)
│   └── ...                         # yaml/properties에서 spring.datasource.* 가져오기 액션
├── api/                            # intellij.phantom.db.api        (v0.3, 다른 phantom 플러그인용)
└── testSrc/ / testData/
```

`plugin.xml` 골격 [가정: 문법은 textmate 예와 같다]

```xml
<idea-plugin>
  <id>com.phantom.db</id>
  <name>Phantom Database Console</name>
  <dependencies>
    <plugin id="com.intellij.modules.lang"/>
    <plugin id="intellij.grid.core.plugin"/>   <!-- 커뮤니티 기본 번들 [검증] -->
    <plugin id="com.intellij.java"/>           <!-- JarRepositoryManager가 intellij.java.ui에 있음 [검증] -->
  </dependencies>
  <content namespace="phantom">
    <module name="intellij.phantom.db.sql"  loading="required"/>
    <module name="intellij.phantom.db.core" loading="required"/>
    <module name="intellij.phantom.db.ui"   loading="required"/>
    <module name="intellij.phantom.db.injection"/>  <!-- v0.2: langInjection + kotlin 있을 때만 -->
    <module name="intellij.phantom.db.spring"/>     <!-- v0.2: yaml + properties 있을 때만 -->
  </content>
</idea-plugin>
```

### 3.3 SQL 하이라이트: TextMate vs 자체 경량 렉서

| 기준 | TextMate (`lib/bundles/sql`) | 자체 경량 렉서 + 평평한 PSI |
|---|---|---|
| 구현 비용 | 거의 0. 이미 번들돼 있고 `.sql`이 다른 파일 타입에 매핑되지 않으면 TextMate가 맡는다 [검증: 번들 존재] / [가정: 현재 phantom 빌드에서 `.sql`이 TextMate로 열림] | 2–3일. 직접 쓴 상태 기계 렉서(약 300–500줄)와 문장 단위 PSI |
| 문법 품질 | VS Code의 **MS SQL(T-SQL) 문법**이다. MySQL 백틱, `#` 주석, PostgreSQL `$$` 본문, `::` 캐스트를 제대로 다룬다고 보장할 수 없다 [가정] | 대상 방언 3개만 정확히 처리한다 |
| 실행 단위(캐럿 문장) 찾기 | TextMate 토큰은 스코프 문자열이라 문장 경계를 안정적으로 잡기 어렵다. 문자열 속 `;`를 판단하려면 결국 별도 스캐너가 필요하다 | 렉서 토큰으로 `;`, `DELIMITER`(MySQL), `$$`를 정확히 다룬다 |
| 완성 컨텍스트 | 불가능(PSI 없음) | `FROM`/`JOIN` 뒤 → 테이블, `alias.` 뒤 → 컬럼 같은 토큰 기반 휴리스틱이 가능하다 |
| Kotlin/Java 문자열 주입 (v0.2) | TextMate 언어를 주입 대상으로 쓰기는 어렵다. 하이라이터가 파일 이름으로 번들을 고르기 때문이다 [가정] | 언어 ID `SQL`로 등록하면 IntelliLang의 `@Language("SQL")`과 바로 맞물린다 [가정] |
| 런타임 비용 | 정규식 엔진(joni) 기반이라 큰 마이그레이션 파일에서 하이라이트 비용이 더 크다 [가정] | 정규식 없는 단일 패스 렉서. 증분 재렉싱(`LexerBase` + 상태 저장) |
| `isMyFileType` 경합 | TextMate 판정기가 모든 파일에 호출된다 [측정: `TextMateFileType.isMyFileType` 샘플 55건] | 확장자 등록만 쓰므로 판정기를 호출하지 않는다 |

**결정**: 자체 경량 렉서로 간다. TextMate는 비교 기준선으로만 쓴다. 즉, 같은 파일에서 두 하이라이트를 눈으로 비교해 자체 렉서가 퇴행하지 않는지 확인한다. 우리 `.sql` 파일 타입을 등록하면 `.sql`은 우리가 맡고, TextMate SQL 번들은 사용자가 원하면 Settings에서 다시 연결할 수 있다.

렉서 설계 [가정: 설계]
- 토큰: `KEYWORD`, `IDENT`, `QUOTED_IDENT`(백틱/큰따옴표/대괄호), `STRING`(`'…'`, `E'…'`, `$tag$…$tag$`), `NUMBER`, `LINE_COMMENT`(`--`, MySQL `#`), `BLOCK_COMMENT`, `OP`, `SEMICOLON`, `PARAM`(`?`, `:name`, `${…}`), `WS`, `BAD`.
- 방언: `SqlDialect { ANSI, MYSQL, POSTGRESQL, H2 }`. 렉서 생성자 인자로만 받는다. 키워드 집합은 방언별 정적 `Set<String>`(대소문자 무시)이다. 키워드는 SQL 표준 예약어와 각 DBMS 공식 문서의 예약어 목록에서 뽑는다.
- 파일의 방언 결정 순서: (1) 콘솔이면 데이터 소스 DBMS. (2) `.sql` 파일이면 사용자 매핑(`FilePropertyPusher` 없이 `PersistentStateComponent`의 경로 접두어 → 방언 맵). (3) 기본값 ANSI. 방언이 바뀌면 그 파일만 재하이라이트한다(`FileContentUtilCore.reparseFiles(file)` [가정: 위치 확인 필요]).
- PSI: `SqlFile` → `SqlStatement*` → 토큰 leaf. 문법 트리를 더 만들지 않는다. 문장 분리와 완성 컨텍스트 계산에만 쓴다.

드라이버 카탈로그 (`core/resources/phantom-db/drivers.json`) [가정: 좌표는 Maven Central 공개 좌표]
- MySQL: `com.mysql:mysql-connector-j`, 클래스 `com.mysql.cj.jdbc.Driver`
- PostgreSQL: `org.postgresql:postgresql`, `org.postgresql.Driver`
- H2: `com.h2database:h2`, `org.h2.Driver`. **H2는 버전이 맞아야 한다.** 파일 DB 포맷이 1.4.x와 2.x 사이에서 호환되지 않으므로, 프로젝트 라이브러리의 H2 버전을 우선 제안한다.
- (선택) MariaDB: `org.mariadb.jdbc:mariadb-java-client`

드라이버 jar 저장 위치: `PathManager.getSystemPath()/phantom-db/drivers/<g>/<a>/<v>/` [검증: `PathManager` 존재]. Gradle 캐시에서 찾은 경우에는 복사하지 않고 그 경로를 참조한다.

### 3.5 연결과 실행 런타임

- `ConnectionManager` (앱 수준 light service)
  - `DriverRef` 해시를 키로 `UrlClassLoader`를 만들고 공유한다. `DriverManager`를 쓰지 않는다. `ServiceLoader.load(Driver::class.java, loader)`로 찾거나 카탈로그의 클래스 이름으로 `Driver` 인스턴스를 만든 뒤 `driver.connect(url, props)`를 직접 부른다. 그래서 전역 `DriverManager` 등록이 남지 않는다 [가정: JDBC 4 표준 동작].
  - 데이터 소스당 연결 1개를 열어 두고 콘솔이 공유한다. 메타데이터 조회는 같은 연결에서 직렬화한다(뮤텍스). v0.2에서 콘솔별 연결을 고려한다.
  - 10분 동안 쓰지 않으면 연결을 닫는다. 데이터 소스를 지우거나 드라이버를 바꾸면 로더를 해제한다. MySQL Connector/J의 정리 스레드는 알려진 정리 API를 리플렉션으로 호출한다 [가정: `AbandonedConnectionCleanupThread.checkedShutdown()`].
  - 프로젝트를 닫을 때 프로젝트 소속 연결을 모두 닫는다(`Disposable` 부모 = 프로젝트 서비스).
- `QueryExecutor`
  - 코루틴 `withContext(Dispatchers.IO)`에서 `Statement.execute`. `setMaxRows(maxRows + 1)`로 잘림 여부를 판단하고, `setFetchSize`(MySQL은 스트리밍 조건이 특수하므로 기본값 유지), `setQueryTimeout`을 건다.
  - 취소는 코루틴 취소 → `Statement.cancel()`이다. 진행 상황은 `withBackgroundProgress`로 보여 주고 취소 버튼을 연결한다 [가정: API 이름 확인 필요].
  - 결과는 `ResultSetMetaData` → `JdbcGridColumn` 목록, 행 → `GridRow`(값은 JDBC `getObject`)로 바꾼다. 큰 LOB은 앞 4 KB만 읽고 표시를 자른다.
  - 여러 결과(`getMoreResults`)는 결과 탭 여러 개로 보여 준다.
- 읽기 전용 데이터 소스에서는 `Connection.setReadOnly(true)`를 걸고, 렉서 첫 키워드가 `SELECT/SHOW/EXPLAIN/WITH/DESCRIBE`가 아니면 실행 전에 확인을 받는다.

### 3.6 캐시와 무효화

| 대상 | 저장 | 무효화 시점 | 범위 |
|---|---|---|---|
| 데이터 소스 설정 | `.idea/phantomDataSources.xml` | 사용자 편집 | 해당 데이터 소스 |
| 비밀번호 | PasswordSafe | 사용자 편집 | 해당 항목 |
| 드라이버 jar | system 경로 | 버전 변경 | 해당 로더 |
| 스키마 메타데이터 | 메모리(Soft, LRU) | Refresh 버튼, 콘솔 DDL 실행 후(`CREATE/ALTER/DROP` + 대상 이름이 보이면 그 스키마 노드, 안 보이면 해당 데이터 소스 루트), 연결 재수립 | **노드 서브트리**. PSI 수정이나 VFS 이벤트로는 무효화하지 않는다 |
| 완성 후보 | `MetadataCache`를 직접 조회 | 위와 같음 | 같음 |
| 렉서 결과 | 플랫폼 하이라이터의 증분 렉싱 | 문서 변경 | 변경 구간 |

`PsiModificationTracker` 같은 전역 추적기를 쓰지 않는다. 그래서 Spring 모델처럼 "파일 하나 수정 → 프로젝트 전체 캐시 무효화"가 생기지 않는다 [측정: README 원장 Q3의 Spring 모델 무효화 문제].

### 3.7 다른 phantom 플러그인과의 경계

- phantom-db는 다른 phantom 플러그인에 의존하지 않는다. 다른 플러그인도 phantom-db에 **하드 의존하지 않는다.**
- v0.3에 `intellij.phantom.db.api` 모듈을 둔다. 인터페이스는 `interface SchemaProvider { fun tables(dataSourceId): List<TableInfo>? }` 하나다. 이 API는 **캐시에 있는 것만** 돌려주고, 연결을 새로 열지 않는다. phantom-jpa는 optional 콘텐츠 모듈(`phantom.jpa.db`, phantom-db가 있을 때만 로드)로 이 API를 소비해서 엔티티 ↔ 컬럼 불일치를 표시한다.
- Flyway 마이그레이션 파일은 `.sql` 파일 타입으로 하이라이트만 받는다. Flyway 전용 기능은 v0.3 이후다.

### 3.8 스레딩 규칙

- EDT에서 하는 일: 트리 노드 펼치기 요청 발행, 그리드 모델 갱신, 대화상자 표시.
- 백그라운드(`Dispatchers.IO`)에서 하는 일: 연결, 쿼리, 메타데이터, 드라이버 해석·다운로드, 프로젝트 라이브러리 스캔(`isApplicableAsync`의 드라이버 존재 확인 포함).
- read action이 필요한 일: `.sql` PSI 문장 분리(`readAction {}`), 완성(플랫폼이 이미 read action 안에서 호출).
- 모든 코루틴 scope는 서비스가 주입받은 `CoroutineScope`의 자식으로 만든다. 프로젝트를 닫으면 함께 취소된다. 영구 collector는 두지 않는다.

### 3.9 Kotlin K2 / UAST (v0.2 주입)

- **K2 Kotlin**: `@Language("SQL")` 주입은 Kotlin 플러그인의 `KotlinLanguageInjectionContributorBase`와 IntelliLang 설정 경로로 처리된다 [검증: 클래스와 `kotlinInjections.k2.xml` 존재]. 우리 언어 ID가 `SQL`이면 추가 코드 없이 동작할 가능성이 높다 [가정].
- **Spring Data `@Query(value = "...", nativeQuery = true)`와 `JdbcTemplate`**: `injection/resources/phantomSqlInjections.xml`에 IntelliLang 주입 패턴(Java)을 넣는다. Kotlin은 `languageInjectionContributor`를 직접 구현한다. 구현 안에서 **UAST**(`UastContextKt.toUElement`, `UAnnotation`, `UCallExpression`)로 애너테이션 속성과 호출 대상을 판정한다. 그래서 Java와 Kotlin(K1/K2) 소스를 같은 코드로 처리한다 [가정: UAST 위치는 `uast/uast-common` 계열].
- **JPQL(`nativeQuery=false`)은 주입하지 않는다.** JPQL은 phantom-jpa의 영역이고, SQL 렉서로 하이라이트하면 잘못된 신호를 준다.
- 판정은 상수 문자열 리터럴에만 한다. 문자열 연결, 템플릿, `trimIndent()`는 v0.2에서 플랫폼 다중 호스트 주입이 허용하는 범위까지만 지원한다.

## 5. 테스트 방법

### 5.1 자동 테스트 (커뮤니티 테스트 프레임워크)

- **렉서 테스트**: `LexerTestCase` 스타일의 골든 파일 비교 [가정: 위치는 `platform/testFramework`의 lexer 테스트 기반 클래스]. `testData/lexer/{mysql,postgresql,h2,ansi}/*.sql` → `*.txt` 토큰 덤프. 경계 사례로 `$$` 중첩, `E'\''`, 백틱 안 `;`, `#` 주석, `DELIMITER //`를 둔다.
- **하이라이트/PSI**: `BasePlatformTestCase` [검증]에서 `myFixture.configureByText("a.sql", …)` → 문장 분리 결과와 캐럿 문장 범위를 확인한다.
- **완성**: `myFixture.completeBasic()`. `MetadataCache`에 가짜 메타데이터를 미리 넣고 테이블/컬럼 후보를 확인한다.
- **실행 런타임**: 테스트 classpath의 **H2 인메모리 DB**(`jdbc:h2:mem:t`)로 연결, 쿼리, 잘림(`maxRows+1`), 취소, 다중 결과, DDL 후 무효화 범위를 검증한다. 격리 로더 테스트는 H2 jar를 별도 로더로 올려 `DriverManager.getDrivers()`에 등록이 남지 않는지 본다.
- **설정 저장**: 직렬화 라운드트립. XML에 비밀번호 필드가 없는지 검사한다.
- **스레딩**: 테스트에서 `ApplicationManager.getApplication().assertIsNonDispatchThread()`를 실행 경로에 넣어 EDT 호출을 잡는다 [가정: 메서드 이름 확인 필요].

### 5.2 수동 확인 (사용자 프로젝트 `~/orca/workspaces/prototype-reservation-system`)

1. 프로젝트를 열고 툴 윈도우가 나타나는지 본다. 드라이버 라이브러리 감지가 동작하는지 확인하는 단계다.
2. 로컬 MySQL(또는 testcontainers로 띄운 MySQL)에 데이터 소스를 만든다. 드라이버는 "프로젝트 라이브러리"를 쓴다. Test Connection을 누른다.
3. 스키마 트리에서 `flyway_schema_history`와 업무 테이블을 펼친다. Flyway 마이그레이션의 컬럼과 비교한다.
4. 콘솔에서 `SELECT`, `UPDATE … WHERE`, `WHERE` 없는 `DELETE`(경고가 떠야 함), `SELECT SLEEP(30)` 후 취소를 해 본다.
5. `infrastructure-module/src/main/resources/db/migration/` 아래 파일을 여러 개 열어 하이라이트를 확인한다.
6. H2 데이터 소스: `jdbc:h2:mem:` 또는 파일 DB. 프로젝트 H2 버전과 드라이버 버전이 일치하는지 본다.
7. IDE를 재시작해서 데이터 소스가 유지되는지, 시작 로그에 phantom-db 초기화가 없는지 본다.

### 5.3 비용 측정 (경량화 목표 검증)

`reversed/`에서 쓴 방법을 그대로 쓴다. 번들 JBR의 `jcmd`와 `jfr`이다.

| 지표 | 방법 | 목표 |
|---|---|---|
| 데이터 소스 0개일 때 적재 클래스 | `jcmd <pid> VM.class_hierarchy` 또는 클래스 히스토그램에서 `com.phantom.db` 접두어 수 | < 150 |
| 콘솔 사용 중 적재 클래스 / metaspace | `VM.classloader_stats`, `VM.metaspace` | < 1,000 클래스, < 5 MB (드라이버 제외) |
| 시작 경로 기여 | startup JFR에서 `com.phantom.db` 프레임이 있는 `jdk.ExecutionSample` | 0개 (시작 활동 없음) |
| 유휴 CPU | 90초 idle JFR | phantom-db 프레임 0 |
| EDT 블록 | freeze 리포트, JFR `jdk.JavaMonitorWait` on EDT | phantom-db 프레임 0 |
| 상주 코루틴 | `Thread.print`의 코루틴 덤프 | 콘솔을 닫은 뒤 phantom-db scope 0개 |

DBN(선택지 a)을 평가할 때도 같은 표로 측정한다. 그래야 두 선택지를 같은 기준으로 비교할 수 있다.

## 7. S5 구현 메모 (2026-10-17)

S5(데이터 소스 하나 연결, SQL 콘솔 실행)를 `plugins/phantom-db`로 구현했다. 설계와 다르게 간 곳과 그 이유를 적는다.

| 설계 | 구현 | 이유 |
|---|---|---|
| 플러그인 ID `com.phantom.db`, 콘텐츠 모듈 3개(`sql`, `core`, `ui`) | `dev.phantom.db`, 콘텐츠 모듈 1개(`intellij.phantom.db.core`) | 다른 phantom 플러그인과 같은 규칙. 세 모듈이 항상 함께 로드되므로 나눌 이득이 없다 |
| 렉서에 `SqlDialect` 플래그 | 방언 구분 없는 렉서 하나 (백틱·큰따옴표·대괄호 식별자, `--`/`#`/`/* */`, `$tag$`, `E''`, `::`) | 세 방언의 문법이 거의 겹치지 않는다. 달라지는 것은 일부 토큰의 색뿐이고 문장 경계는 같다. 상태가 항상 0이라 증분 재렉싱이 단순하다 |
| 드라이버를 Maven Central에서 내려받기(`JarRepositoryManager`) | 직접 고른 jar → 프로젝트 라이브러리 → `~/.gradle`·`~/.m2` 캐시 순서로 찾기. 내려받기는 없음 | 사용자 프로젝트는 이미 드라이버를 의존성으로 갖고 있다. Java 플러그인 의존과 네트워크 경로를 v0.2로 미룬다 |
| 결과는 콘솔 아래 | 아래쪽 "DB Results" 툴 윈도우. 첫 실행 때 등록되고, 콘솔(또는 `.sql` 파일)마다 탭 하나를 재사용한다 | phantom-http의 응답 창과 같은 방식 |
| 콘솔 `LanguageConsoleImpl` 또는 실제 파일 (Q2) | 실제 파일 `config/phantom-db/consoles/<데이터 소스 id>/<이름>.sql` | 재시작 후에도 남고, 폴더 이름으로 데이터 소스를 알 수 있다. 다른 `.sql` 파일은 워크스페이스 설정으로 데이터 소스에 연결한다 |
| 읽기 전용이면 실행 전 확인 | 읽기 전용이면 읽기 문장 외에는 실행하지 않음 + `Connection.setReadOnly(true)` | 확인 후 실행해도 읽기 전용 연결이 거부하므로 확인 창이 의미가 없다 |
| 메타데이터 캐시 소프트 참조 + LRU 2,000 | 일반 맵(이름과 타입만), Refresh와 DDL 실행 때 데이터 소스 단위로 비움 | 이름 목록이라 크기가 작다. 큰 스키마에서 측정한 뒤 필요하면 상한을 둔다 |

커뮤니티 그리드는 `CachedGridDataHookUp` + `GridUtil.createDataGrid`로 쓴다. 그리드는 만들 때 `GridHelper` 등을 기대하므로, 커뮤니티 CSV 뷰어와 같은 `GridUtil.configureCsvTable` 설정을 먼저 적용한다. 행은 `GridStorageAndModelUpdater`로 넣어야 그리드가 열·행 이벤트를 받는다 (R2 확인).

확인한 것
- 테스트 11개: 렉서(재시작 포함 3개), 문장 분리와 캐럿 문장, 안전장치, 저장 XML에 비밀번호 없음, 드라이버 찾기(캐시·프로젝트 라이브러리), H2 실행(별도 클래스 로더, 행 상한, 실패 시 중단), 실행 중 취소, 스키마 트리 지연 로드와 캐시 기반 완성, Run 거터와 결과 창 탭 재사용.
- 사용자 로컬 MySQL(Docker, `compose.yaml`의 개발 계정)에 읽기 전용 데이터 소스로 연결: 드라이버는 Gradle 캐시의 `mysql-connector-j-9.1.0`, 스키마 2개, 테이블 24개, 컬럼과 PK, `SELECT`, `SELECT SLEEP(30)` 취소 27 ms, 취소 뒤 같은 연결 재사용. 확인용 임시 테스트는 지웠다.
- 사용자 프로젝트의 `.sql` 파일 28개(문장 71개)를 렉싱해 잘못된 문자 토큰 0개.
