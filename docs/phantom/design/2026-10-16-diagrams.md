# phantom-diagrams 설계: Spring 빈 그래프, JPA 엔티티 관계도, DB ER 다이어그램

- 날짜: 2026-10-16
- 대상 트리: `phantom-idea` (intellij-community `idea/262.10968.63` 포크), Bazel 빌드
- 사용자: Kotlin + Spring Boot + JPA + Gradle 백엔드 개발자. 기준 프로젝트는 `~/orca/workspaces/prototype-reservation-system/infro`다
- 클린룸 원칙: Ultimate 쪽 입력은 (1) `Intellij-rea/reversed/` 노트의 **동작·비용 서술**(`README.md`, `02-runtime/2026-10-16-startup-jfr.md`, `03-decompiled/2026-10-16-ult-other-plugins.md`, `ult-lib-closed.md`, `ult-spring-javaee.md`, `ult-database.md`)과 (2) 설치본 plugin.xml에서 뽑은 **기능 이름 목록**뿐이다. 디컴파일 소스(`reversed/source/`)는 열지 않았다. 아래 구조는 community API, Mermaid 공개 문서, JPA/JDBC 공개 스펙으로 새로 설계했다. 라이선스·인증 코드는 다루지 않는다.

표기
- **[검증]**: 이 트리(또는 사용자 프로젝트)에서 경로, 클래스, 시그니처, 값을 직접 확인했다
- **[가정]**: 공개 문서나 일반 지식, 설계 판단에 기댄 것이다. 구현 첫 단계(T0 스파이크)에서 확인한다
- **[측정]**: `reversed/` 노트에 기록된 Ultimate 실측값이다

## 1. 목표와 범위

### 1.1 사용자 프로젝트 규모 [검증, 읽기 전용 grep]

| 항목 | 값 | 설계에 주는 의미 |

### 1.3 MVP (v0.1)

| # | 기능 | 사용자가 보는 것 |
|---|---|---|
| D1 | **Spring 빈 의존 그래프 (초점 모드)** | 클래스나 `@Bean` 메서드에서 `Diagrams > Show Bean Dependencies`를 고르면 에디터 탭이 열린다. 그 빈이 의존하는 빈(기본 깊이 2), 그 빈에 의존하는 빈(기본 깊이 1)이 Gradle 모듈별 박스 안에 그려진다 |
| D1a | **패키지/모듈 범위 그래프** | Project 뷰에서 패키지나 모듈을 고르면 그 안의 빈 사이 의존만 그린다. 바깥 빈은 회색 "경계" 노드로 한 번만 나온다 |
| D1b | **문제 표시** | 해석 안 된 주입은 빨간 점선 노드 `?: TypeName`, 후보가 여럿이면 주황 간선, 순환(강한 연결 요소 크기 2 이상)은 빨간 간선과 상단 경고 줄로 보인다. Spring Boot 2.6부터 순환 참조가 기본 금지라 실무에서 쓸모가 있다 [가정: Boot 공개 문서] |
| D2 | **JPA 엔티티 관계도** | 엔티티 파일이나 패키지에서 `Diagrams > Show Entity Relations`. 모듈의 `@Entity`, `@MappedSuperclass`, `@Embeddable`과 관계(카디널리티, 소유 측, `mappedBy` 짝)를 ER 표기로 그린다. 속성 표시는 토글이다 |
| V1 | **공용 뷰어** | 줌(Ctrl+휠, 맞춤), 팬, 노드 검색(일치 노드 강조), IDE 테마(밝게/어둡게) 연동 |
| V2 | **소스로 이동** | 노드 클릭 → 클래스나 `@Bean` 메서드, 엔티티 선언으로 이동. 간선 클릭 → 주입 지점(생성자 파라미터, 필드) 또는 관계 필드로 이동 |
| V3 | **필터** | 스테레오타입별 숨김(`@Configuration`, `@ConfigurationProperties`, Spring Data 리포지토리), 깊이(1–4), 테스트 소스 제외, "인터페이스 노드 보기" 토글(포트 인터페이스를 노드로 보일지, 구현으로 바로 이을지) |
| V4 | **내보내기** | SVG 저장, PNG 저장(배율 1x/2x), Mermaid 소스 저장(`.mmd`, Mermaid 플러그인 편집기로 열림), Mermaid 소스 복사 |
| V5 | **신선도** | 모델이 바뀌면 탭 상단에 "모델이 바뀌었습니다 · 새로 고침" 배너를 띄운다. 탭이 보이는 상태에서만 1초 디바운스 후 자동 갱신(설정으로 끔) |
| V6 | **JCEF 없는 환경** | 그래프를 `.mmd` 텍스트 탭으로 열고 알림을 띄운다 |

### 1.4 v0.2 이후

- **v0.2**
  - D3 **DB ER 다이어그램**: phantom-db의 스키마 캐시(테이블, 컬럼, PK, FK)에서 그린다. 노드 클릭 → Database 툴 창에서 테이블 선택. phantom-db의 `SchemaProvider` API가 필요하다 (6절 R6)
  - D2 + D3 **겹쳐 보기**: 엔티티 ↔ 테이블 매핑 불일치(없는 테이블, 없는 FK) 표시
  - 다이어그램 저장: 필터와 초점을 `.idea/phantomDiagrams.xml`에 이름 붙여 저장하고 다시 연다
  - 라이브러리 빈(자동 구성)을 접힌 노드 하나로 표시 (phantom-spring v0.2 자동 구성 모델이 들어온 뒤)
- **v0.3**
  - 렌더러 교체 옵션: ELK + Swing 렌더러(JCEF 없이, 큰 그래프용). `DiagramRenderer` 인터페이스 두 번째 구현
  - 증분 렌더링: 노드 집합이 같으면 레이아웃을 유지하고 스타일만 바꾼다
  - `@EventListener` ↔ `publishEvent` 이벤트 흐름 그래프 (phantom-spring v0.2 거터 데이터 재사용)

### 1.5 비목표

- 다이어그램에서 코드를 만들거나 고치는 편집형 UML (노드 추가, 이름 바꾸기, 되돌리기)
- 일반 Java/Kotlin 클래스 계층 UML, Maven/Gradle/Java 모듈 의존 다이어그램, VCS 변경 다이어그램

- 손으로 노드 위치를 옮겨 저장하는 기능 (자동 레이아웃만)
- 온라인 편집기로 열기, 외부 서비스 전송 (사용자 코드가 밖으로 나간다)

- 900개 빈 전체 그래프 (초점·범위 그래프로 대신한다)

| (일반) 그래프를 EDT에서 그린다 | `ult-lib-closed.md` 97행 "EDT 렌더링" | JVM 쪽에서는 그래프 계산, 텍스트 생성 모두 백그라운드에서 한다. 그리기는 CEF 렌더 프로세스가 한다. EDT는 탭 컴포넌트 생성과 에디터 열기만 한다 |

추가 원칙
1. **기술을 쓸 때만 켠다.** D1 진입 액션은 phantom-spring의 `SpringProjectGate.isActive(project)`가 참일 때만 보인다. D2는 phantom-jpa의 `JpaFacade.isEnabled(module)`, D3는 phantom-db 데이터 소스가 하나 이상 있을 때만 보인다. 게이트 함수는 각 소스 플러그인 것을 그대로 쓴다.
2. **JCEF 수명 = 탭 수명.** 탭을 닫으면 `JBCefBrowser`와 `JBCefJSQuery`를 `Disposer`로 해제한다. 탭이 여러 개면 브라우저도 여러 개지만, 한 프로젝트에 다이어그램 탭은 보통 1–2개다. 상한(기본 4개, 넘으면 가장 오래 안 본 탭의 브라우저를 해제하고 다시 보일 때 만든다)을 둔다.
3. **필터는 JVM에서, 그리기는 브라우저에서.** 필터를 바꾸면 그래프를 다시 잘라 Mermaid 텍스트를 다시 만든다. JS에는 로직을 두지 않는다(심은 렌더, 클릭 전달, 내보내기만 한다). 그래서 JS를 테스트할 일이 적다.
4. **상한을 먼저 건다.** 노드 150, 간선 400을 넘으면 그리지 않고 "필터를 좁히세요"와 함께 상위 N개 노드만 보여 준다 (3.6절).

### 3.3 내부 확장점과 데이터 모델

```kotlin
// core/api — 소스 플러그인 어댑터가 구현한다 (diagrams 플러그인 안의 optional 모듈에만 구현이 있음)
interface DiagramSource {
  val kind: DiagramKind                                     // SPRING_BEANS, JPA_ENTITIES, DB_SCHEMA
  fun isAvailable(project: Project): Boolean                // 게이트. 싸야 한다 (인덱스·PSI 금지)
  fun modelVersion(project: Project): Long                  // 소스 스냅숏 버전. 신선도 판단용
  suspend fun build(project: Project, request: DiagramRequest): DGraph   // 전체 후보 그래프 (자르기 전)
}

data class DiagramRequest(
  val kind: DiagramKind,
  val scope: Scope,                                         // Focus(nodeKey) | Package(fqn, moduleName) | Module(name) | DataSource(id, schema)
  val filter: DiagramFilter,
)

data class DiagramFilter(
  val depthOut: Int = 2, val depthIn: Int = 1,
  val hiddenNodeKinds: Set<NodeKind> = setOf(NodeKind.CONFIG_PROPERTIES),
  val includeTests: Boolean = false,
  val showInterfaces: Boolean = false,                      // D1: 포트 인터페이스 노드
  val showAttributes: Boolean = true,                       // D2/D3: 속성·컬럼
  val groupBy: GroupBy = GroupBy.GRADLE_MODULE,             // NONE, GRADLE_MODULE, PACKAGE
  val search: String? = null,
)
```

```kotlin
// core/model — 불변, PSI 없음
data class DGraph(
  val kind: DiagramKind,
  val nodes: List<DNode>, val edges: List<DEdge>, val groups: List<DGroup>,
  val sourceVersion: Long,
  val truncated: Truncation? = null,                        // 상한에 걸렸을 때: 원래 수, 남긴 수, 이유
  val warnings: List<String> = emptyList(),                 // "순환 2개", "해석 안 된 주입 3개"
)

data class DNode(
  val key: String,                                          // 안정 키: "bean:<name>@<module>", "entity:<fqn>", "table:<ds>/<schema>.<t>"
  val label: String, val subLabel: String?,                 // 빈 이름 / 타입 단순 이름
  val kind: NodeKind,                                       // COMPONENT, SERVICE, REPOSITORY, CONTROLLER, CONFIGURATION, BEAN_METHOD,
                                                            // DATA_REPOSITORY, CONFIG_PROPERTIES, INTERFACE, UNRESOLVED, BOUNDARY,
                                                            // ENTITY, MAPPED_SUPERCLASS, EMBEDDABLE, TABLE
  val groupKey: String?,
  val attributes: List<DAttr> = emptyList(),                // D2/D3: name, type, PK/FK/UK
  val location: Location?,
  val flags: Set<NodeFlag> = emptySet(),                    // FOCUS, IN_CYCLE, TEST_SOURCE, LIBRARY, SEARCH_HIT
)

data class DEdge(
  val from: String, val to: String,
  val kind: EdgeKind,                                       // INJECTS, INJECTS_MULTI, INJECTS_OPTIONAL, AMBIGUOUS, UNRESOLVED,
                                                            // MANY_TO_ONE, ONE_TO_MANY, ONE_TO_ONE, MANY_TO_MANY, EMBEDS, EXTENDS, FK
  val label: String?,                                       // 주입 지점 이름, 관계 필드 이름, FK 이름
  val ends: Cardinality? = null,                            // (fromEnd, toEnd): ZERO_ONE, ONE, ZERO_MANY, ONE_MANY
  val bidirectional: Boolean = false,                       // mappedBy 짝을 합친 간선
  val location: Location?,                                  // 주입 지점 / 소유 측 필드
  val flags: Set<EdgeFlag> = emptySet(),                    // IN_CYCLE
)

data class Location(val fileUrl: String, val offset: Int, val fallbackFqn: String?, val memberName: String?)
```

- 노드 키는 문자열이지만 Mermaid 텍스트에는 넣지 않는다. 이미터가 `n0, n1, ...` 짧은 id를 붙이고 `id → key` 표를 렌더 결과와 함께 들고 있다. 클릭이 오면 `n17 → key → Location`으로 찾는다. 사용자 문자열(빈 이름, 컬럼 이름)이 Mermaid 문법을 깨지 않게 하려는 것이다.
- `Location`은 소스 플러그인이 이미 들고 있는 값이다. phantom-spring은 `BeanDef.location`, `InjectionPointRecord.offset`을 [검증: phantom-spring 설계 3.3절], phantom-jpa는 `JpaAttribute.element`(PSI)를 들고 있으므로 어댑터에서 `(virtualFile.url, textOffset)`으로 바꾼다 [검증: phantom-jpa 설계 3.3절]. 오프셋이 낡았으면 `fallbackFqn`/`memberName`으로 `JavaPsiFacade`·UAST 조회를 한 번 한다.

### 3.4 소스별 그래프 구성

#### D1 Spring 빈 (`SpringBeanGraphSource`)

입력은 phantom-spring의 `BeanRegistrySnapshot`(`beansByType`, `injectionPointsByType`, `version`)과 `InjectionResolver`다 [검증: phantom-spring 설계 3.3절의 이름. 공개 API로 노출하는 것은 그 플러그인과 합의해야 한다, 6절 R5].

1. 노드: 스냅숏의 `BeanDef` 전부를 후보로 둔다. `kind`는 `BeanSource`와 스테레오타입으로 정한다 (`STEREOTYPE`+`@Service` → `SERVICE`, `BEAN_METHOD` → `BEAN_METHOD`, `DATA_REPOSITORY`, `CONFIG_PROPS`). 사용자 메타 스테레오타입(`@UseCase`)은 노드 부제에 `«UseCase»`로 보인다.
2. 간선: 빈마다 그 빈의 주입 지점(생성자 파라미터, `@Autowired` 필드·세터, `@Bean` 메서드 파라미터)을 `InjectionResolver`로 풀어서 `소비자 → 후보` 간선을 만든다.
   - 후보 1개 → `INJECTS`. `List<T>`/`Map<String,T>`/`ObjectProvider<T>` → 후보마다 `INJECTS_MULTI`(점선). nullable, `required=false`, `Optional` → `INJECTS_OPTIONAL`.
   - 후보 0개 → `UNRESOLVED` 간선과 `?: Type` 노드. phantom-spring이 "모름"(라이브러리 타입이라 판단 보류)으로 돌려준 것은 `LIBRARY` 경계 노드로 그리고 빨갛게 칠하지 않는다.
   - 후보 여러 개 → 후보마다 `AMBIGUOUS`(주황).
   - `showInterfaces=true`면 `소비자 → 선언 타입(인터페이스) → 구현`으로 두 단계 간선을 그린다. 헥사고날 포트를 볼 때 쓴다. 기본은 꺼서 간선 수를 줄인다.
3. 그룹: `ModuleUtilCore.findModuleForFile`로 Gradle 소스 세트 모듈을 찾고, `infro.adapter-module.main` 같은 IDE 모듈 이름을 Gradle 모듈 이름(`adapter-module`)으로 줄인다 [가정: Gradle import가 만드는 모듈 이름 규칙, T6에서 확인].
4. 순환: 자르기 전에 전체 빈 그래프에서 `DFSTBuilder`로 강한 연결 요소를 구한다. 크기 2 이상인 요소의 간선에 `IN_CYCLE`을 붙인다. 초점 그래프에 순환 일부만 들어와도 경고 줄에 전체 순환 경로를 적는다.

#### D2 JPA 엔티티 (`JpaEntityGraphSource`)

입력은 phantom-jpa의 `JpaFacade`(`getEntityModel(cls)`, `allEntityNames(module)`)다 [검증: phantom-jpa 설계 3.3절]. 모듈의 엔티티 클래스 목록이 필요하므로 `allEntityClasses(module): Collection<PsiClass>`(또는 포인터) 추가를 요청한다 (6절 R5).

1. 노드: `ENTITY`(`@Entity`), `MAPPED_SUPERCLASS`, `EMBEDDABLE`. 속성은 `JpaAttribute`의 `name`, `valueType` 단순 이름, `kind`(ID → PK, 관계 소유 측 `@JoinColumn` → FK).
2. 간선:
   - `MANY_TO_ONE`, `ONE_TO_ONE`(소유 측), `ONE_TO_MANY`, `MANY_TO_MANY`를 관계 속성마다 하나씩 만든다.
   - **양방향 합치기**: 반대쪽 속성의 `mappedBy`가 이쪽 속성 이름과 같으면 두 간선을 `bidirectional=true` 하나로 합친다. 소유 측(외래 키를 가진 쪽)을 `from`으로 둔다. `mappedBy`가 가리키는 속성이 없으면 경고를 단다 (phantom-jpa 검사와 같은 판단).
   - 카디널리티: `ManyToOne` 소유 측 → `(ZERO_MANY, ZERO_ONE)`. `optional=false`이거나 Kotlin 타입이 non-null이면 대상 끝을 `ONE`으로 둔다 [가정: Kotlin null 여부를 JPA 의미로 보는 것은 표시용 근사].
   - `@Embedded` → `EMBEDS`(합성 표기), `@MappedSuperclass` 상속 → `EXTENDS`.
3. 범위 기본값: 선택한 파일의 모듈과 그 의존 모듈의 엔티티. 같은 FQN 엔티티가 여러 작업 공간에 있을 수 있어서 프로젝트 전체 범위를 쓰지 않는다 [검증: phantom-jpa 설계 3.3절 "같은 FQN 엔티티가 4벌"].

#### D3 DB 스키마 (`DbSchemaGraphSource`, v0.2)

입력은 phantom-db의 `SchemaProvider`(캐시에 있는 것만 돌려줌)다 [검증: phantom-db 설계 3.7절. 그 문서에서는 v0.3 계획이다]. FK 정보(`DatabaseMetaData.getImportedKeys`, JDBC 표준)가 캐시에 있어야 한다. phantom-db v0.1 스키마 트리에 FK 노드가 있으므로 [검증: phantom-db 설계 1.2절 5번] 데이터는 있다. 캐시가 비었으면 "Database 툴 창에서 스키마를 펼치거나 Refresh 하세요" 안내를 낸다. **다이어그램이 연결을 새로 열지 않는다.**

### 3.5 Mermaid 텍스트 생성 (`MermaidEmitter`)

- D1: `flowchart LR`. 그룹은 `subgraph g0 ["adapter-module"] ... end`. 노드 모양은 종류별로 다르게 한다(`SERVICE` 둥근 사각형, `CONFIGURATION` 육각형, `DATA_REPOSITORY` 원통, `UNRESOLVED` 점선). 스타일은 `classDef`로 정의하고 `class n3 cycle`처럼 붙인다. 간선: `-->`(필수), `-.->`(선택·다중), `==>`(초점에서 나가는 1단계).
- D2, D3: `erDiagram`. 엔티티와 속성 블록, 관계 `n1 }o--|| n2 : "reservation"`. 카디널리티 기호는 Mermaid ER 표기(`|o`, `||`, `}o`, `}|`)로 옮긴다 [가정: Mermaid 공개 문서의 ER 문법].
- 초기화 옵션(`mermaid.initialize`): `securityLevel: "strict"`, `startOnLoad: false`, `theme`는 IDE 테마에 맞춰 `default`/`dark`, `flowchart.htmlLabels: false`(라벨을 SVG `<text>`로, 3.8절 PNG 이유), `maxEdges: 600`, `maxTextSize: 200000`.
- **클릭은 Mermaid `click` 문법을 쓰지 않는다.** `securityLevel: "strict"`에서는 콜백이 막히고, `erDiagram`은 `click`을 지원하지 않는다 [가정: Mermaid 공개 문서]. 대신 렌더가 끝난 뒤 심이 SVG를 훑어 노드 요소의 `id`에서 짧은 id(`n17`)를 찾아 리스너를 붙인다. flowchart는 `flowchart-n17-<k>`, erDiagram은 `entity-n17-<k>` 형태로 id가 만들어진다 [가정: Mermaid 11 출력 형식, **T0 스파이크에서 반드시 확인**, 6절 R1]. 간선은 flowchart에서 `L_n3_n17_0` 형태 id를 쓴다 [가정].
- 이스케이프: 라벨은 `"..."`로 감싸고 `"`, `<`, `>`, `#`, `;`, 백틱을 Mermaid 엔티티 코드(`#quot;` 등)로 바꾼다. 빈 이름이나 컬럼 이름이 문법을 깨는 경우를 골든 테스트로 막는다.
- 출력은 결정적이어야 한다(노드·간선 정렬 고정). 같은 그래프면 같은 텍스트가 나와야 골든 테스트가 가능하고, 레이아웃이 매번 흔들리지 않는다.

### 3.6 자르기와 상한 (`GraphSlicer`)

1. 범위 적용: `Focus`면 초점 노드에서 나가는 방향 BFS `depthOut`, 들어오는 방향 BFS `depthIn`. `Package`/`Module`이면 범위 안 노드 + 범위 밖 이웃을 `BOUNDARY` 노드로 하나씩.
2. 필터 적용: `hiddenNodeKinds` 노드를 지우되, 지운 노드를 거쳐 가던 의존은 끊긴 채 둔다(가짜 간선을 만들지 않는다). 테스트 소스 제외.
3. 상한: 노드 150 또는 간선 400을 넘으면 초점에서 가까운 순(BFS 거리, 그다음 차수)으로 남기고 `Truncation`을 단다. 배너에 "312개 중 150개 표시 · 깊이를 줄이거나 필터를 거세요"를 보인다.
4. 이 단계는 순수 함수다. PSI도 읽기 락도 쓰지 않는다. 필터 토글은 이 단계와 이미터만 다시 돈다 (목표 50 ms 미만 [가정]).

### 3.7 캐시와 무효화

| 대상 | 저장 | 무효화 | 범위 |
|---|---|---|---|
| 후보 그래프 `DGraph` (자르기 전) | 열린 `DiagramEditor` 필드 | `source.modelVersion(project)`가 달라졌을 때 | 그 탭 하나 |
| 잘린 그래프, Mermaid 텍스트, id 표 | 같은 곳 | 필터 변경 또는 후보 그래프 교체 | 그 탭 하나 |
| 렌더된 SVG | 브라우저 DOM | 새 텍스트 렌더 | 그 탭 하나 |
| 프로젝트·앱 수준 캐시 | **없음** | — | — |

- 신선도 확인은 폴링이다. 탭이 **보이는 동안에만** 2초마다 `modelVersion`을 읽는다(정수 비교 한 번). 리스너를 등록하지 않으므로 탭이 닫히면 비용이 0이 된다. 버전이 바뀌면 배너를 띄우고, 자동 갱신이 켜져 있으면 1초 디바운스 뒤 `build`를 다시 부른다.
- `build`는 소스 플러그인의 스냅숏을 읽기만 한다. 다이어그램 때문에 소스 모델이 다시 계산되지는 않는다. 다만 스냅숏이 아직 없으면(첫 사용) 소스 플러그인이 만드는 비용이 처음 한 번 든다. 이것은 소스 플러그인 비용이다.
- 소스 쪽 `version` 계약: phantom-spring의 `BeanRegistrySnapshot.version` [검증: 설계 3.3절]. phantom-jpa는 파일 단위 `CachedValue`라 전역 버전이 없다. 그래서 D2는 "엔티티 파일 목록과 각 파일의 `modificationStamp` 합"을 버전으로 쓴다 [가정: 24개 파일이라 싸다]. D3는 phantom-db `MetadataCache`의 로드 시각(`loadedAt`) 최댓값이다.

`JcefMermaidRenderer`
- 브라우저를 만들 때 `JBCefBrowserBuilder`에 오프스크린 렌더링과 전용 `JBCefClient`를 준다. `DiagramStaticServer`(우리 `HttpRequestHandler`)가 `/phantom-diagrams/<token>/host.html`, `shim.js`, `mermaid.min.js`를 돌려준다. `<token>`은 IDE 세션마다 만든 난수다. 로컬 내장 서버라도 다른 페이지가 경로를 추측해 읽지 못하게 하려는 것이다.
- `shim.js`가 하는 일 (약 150줄 [가정])
  - `window.phantomRender(encodedText, theme)`: `mermaid.render(id, text)`로 SVG를 만들어 넣고, 노드·간선 요소에 `data-pid`와 클릭 리스너를 붙인다. 오류는 문자열로 돌려준다 (`MermaidApi.render`가 Promise를 돌려주는 형태는 [검증: `plugins/mermaid/browser/mermaid-api/src/main/kotlin/com/intellij/mermaid/api/MermaidApi.kt` 7행]).
  - 클릭 → `JBCefJSQuery` 함수 호출 (`{"t":"node","id":"n17"}`).
  - 줌·팬: SVG `viewBox`를 조절한다. 외부 라이브러리를 쓰지 않는다.
  - `window.phantomExportSvg()`: `<svg>`의 `outerHTML`. 스타일은 Mermaid가 SVG 안 `<style>`에 넣으므로 그대로 독립 파일이 된다 [가정].
  - `window.phantomExportPng(scale)`: SVG를 `Image`로 그려 `canvas.toDataURL("image/png")`의 base64를 돌려준다. `htmlLabels:false`로 `foreignObject`를 없앴으므로 캔버스 오염(taint) 문제가 생기지 않을 것으로 본다 [가정, T0 확인]. 실패하면 JVM에서 SVG를 JSVG `renderSvg(data, scale)`로 래스터화한다 [검증: `svg.kt` 175행].
- JVM → JS 문자열 전달은 base64로 인코딩한다(Mermaid 플러그인도 `PreviewEncodingUtil.encodeContent`로 인코딩해 넘긴다 [검증: `MermaidDiagramPreviewComponent.kt`]).
- 테마: `LafManagerListener`를 탭 수명(Disposable)에 묶어 등록하고, 바뀌면 다시 렌더한다. 탭이 없으면 리스너도 없다.

`TextFallbackRenderer`: JCEF가 없거나 `ide.browser.jcef.enabled=false`면 [검증: `JBCefApp.java` 473행] Mermaid 텍스트를 읽기 전용 에디터로 보인다. 노드 이동은 없다. "`.mmd`로 저장" 버튼은 그대로 있다.

### 3.9 스레딩

| 일 | 스레드 |
|---|---|
| 액션 `update()` | BGT (`ActionUpdateThread.BGT`). 게이트 함수만 부른다. JCEF, PSI, 인덱스를 건드리지 않는다 |
| 커서 위치에서 초점 빈·엔티티 찾기 | `actionPerformed` → 코루틴 `smartReadAction(project) { element.getUastParentOfType(UClass::class.java) }` |
| `DiagramSource.build` | `Dispatchers.Default` + `smartReadAction`. 취소 가능. dumb mode면 "인덱싱이 끝나면 그립니다" 배너를 띄우고 기다린다 |
| 자르기, 텍스트 생성 | `Dispatchers.Default`, 락 없음 |
| 렌더, 내보내기 JS 호출 | `executeJavaScript`(suspend). 결과 대기는 백그라운드 |
| `JBCefJSQuery` 핸들러 | CEF 스레드에서 불린다 [가정]. 즉시 코루틴으로 넘긴다. 위치 해석은 `readAction`, 에디터 열기만 `withContext(Dispatchers.EDT)` |
| 파일 쓰기(내보내기) | `Dispatchers.IO`, 끝나면 `VfsUtil.markDirtyAndRefresh` (Mermaid `ExportDiagramAction`과 같은 방식 [검증]) |

EDT에서 하는 일은 탭 컴포넌트 생성, 툴바 갱신, 에디터 열기뿐이다.

### 3.10 Kotlin K2 / UAST

- 다이어그램은 Kotlin PSI를 직접 읽지 않는다. 빈과 엔티티 모델은 phantom-spring(K2 요약기), phantom-jpa(light class)가 만든다. 그래서 K1/K2 차이는 소스 플러그인 몫이다.
- 다이어그램이 PSI를 만지는 곳은 두 곳이다. (1) 진입 액션에서 커서 아래 클래스·메서드를 찾을 때 UAST `getUastParentOfType`를 쓴다 [검증: `UastContext.kt` 193행]. K2 UAST 구현은 `plugins/kotlin/uast/`에 있다 [검증: phantom-jpa 설계 3.2절]. (2) `Location` 오프셋이 낡았을 때 이름으로 다시 찾는 보조 경로다. Kotlin 선언은 `navigationElement`로 `KtClass`/`KtProperty` 위치를 쓴다.
- Kotlin 주 생성자 파라미터 주입 지점의 위치는 `KtParameter` 오프셋이어야 간선 클릭이 생성자 파라미터로 간다. 이것은 phantom-spring 요약기의 `InjectionPointRecord.offset`이 이미 그렇게 저장한다고 본다 [가정, T6에서 확인].

### 5.1 자동 테스트 (community 테스트 프레임워크)

- **core 단위 테스트** (`UsefulTestCase` 또는 순수 JUnit) [검증: `platform/testFramework/src/com/intellij/testFramework/UsefulTestCase.java`]
  - `GraphSlicerTest`: 깊이, 방향, 숨김 종류, 상한 절단 순서, 경계 노드.
  - `MermaidEmitterTest`: `testData/emit/*.txt` 골든 파일. 따옴표·꺾쇠·한글·`#`가 들어간 이름, 빈 그룹, 자기 자신 간선, 양방향 합치기.
  - 순환: `DFSTBuilder` 결과로 `IN_CYCLE` 표시가 맞는지.
- **어댑터 라이트 테스트** (`LightJavaCodeInsightFixtureTestCase`) [검증: `java/testFramework/src/com/intellij/testFramework/fixtures/LightJavaCodeInsightFixtureTestCase.java`]
  - Spring: Java/Kotlin 픽스처(`@Service` 둘, 생성자 주입, `List<T>` 주입, 미해석 주입, 순환 A→B→A)로 `SpringBeanGraphSource.build`의 노드·간선 집합을 비교한다. Spring 애너테이션은 phantom-spring 테스트가 쓰는 모의 라이브러리를 재사용한다.
  - JPA: `@Entity` 셋, `@ManyToOne` + `@OneToMany(mappedBy)` 쌍, `@Embedded`, `@MappedSuperclass`. 합쳐진 간선 1개, 카디널리티 값을 확인한다.
  - Kotlin 픽스처는 K2 모드 테스트 베이스를 쓴다 (phantom-spring/jpa 테스트 구성과 같게 한다 [가정]).
- **렌더러 통합 테스트**는 CI 헤드리스에서 JCEF가 꺼질 수 있으므로 [검증: `JBCefApp.java` 477행 `ide.browser.jcef.headless.enabled`] 기본적으로 건너뛴다(`assumeTrue(JBCefApp.isSupported())`). 로컬에서는 고정 화면 크기로 렌더해 SVG에 `data-pid`가 노드 수만큼 있는지 본다. Mermaid 플러그인도 테스트에서 고정 해상도를 쓴다 [검증: `Browser.kt`의 `withScreenBounds(1920, 1080)`].

### 5.2 사용자 프로젝트 수동 확인 (`~/orca/workspaces/prototype-reservation-system/infro`)

1. `application-module`의 `@UseCase` 클래스 하나에서 **Show Bean Dependencies**: 포트 인터페이스의 구현(adapter-module)이 다른 모듈 박스 안에 보이는가. 노드 클릭이 구현 클래스로, 간선 클릭이 생성자 파라미터로 가는가.
2. `showInterfaces` 토글: 포트 인터페이스 노드가 사이에 들어오는가.
3. `adapter-module` 패키지 하나에서 **패키지 범위 그래프**: 바깥 빈이 회색 경계 노드로 한 번씩만 나오는가. 상한에 걸리면 배너가 나오는가.
4. 테스트에서 일부러 순환(A→B→A)을 만들면 빨간 간선과 경고 줄이 나오는가. 되돌리면 배너 → 새로 고침 뒤 사라지는가.
5. 엔티티 패키지에서 **Show Entity Relations**: 24개 엔티티, `@Embeddable` 9종, `@MappedSuperclass` 1개가 맞게 표기되는가. 양방향 관계가 한 간선인가.
6. SVG/PNG/`.mmd` 내보내기 결과를 열어 본다. `.mmd`를 `docs/`에 두면 Markdown 미리보기에서도 그려지는가 (Mermaid 플러그인 기능).
7. 다크/라이트 테마 전환, 탭 닫기 후 프로세스 수 확인.

남은 의문
- 900개 빈 중 초점 그래프로 실제로 자주 볼 범위는 어디인가. 사용 로그 없이 정한 기본 깊이 2/1은 T6 수동 점검에서 조정한다.
- D2를 `erDiagram`으로 할지 `classDiagram`으로 할지. ER 표기가 JPA 카디널리티에 맞지만, 상속(`EXTENDS`)은 `classDiagram`이 더 자연스럽다. v0.1은 `erDiagram`으로 하고 상속은 라벨 `«extends»` 관계로 표기한다. T0에서 두 출력을 나란히 보고 정한다.
- 저장한 `.mmd`를 저장소에 커밋해 문서로 쓰는 흐름(코드와 어긋남 감지)을 v0.2 이후에 넣을지.
