## 2. 진행 방식: 얇게 자른 조각부터

한 플러그인의 MVP를 다 만들고 다음으로 가지 않는다. 각 P0 플러그인에서 "사용자가 바로 체감하는 첫 기능 하나"를 먼저 만들고 실제 프로젝트(`~/orca/workspaces/prototype-reservation-system`)에서 확인한다.

| 조각 | 내용 | 상태 |
|---|---|---|
| S1 | phantom-spring: 주입 지점 ↔ Bean 거터(클릭 시 탐색), Spring Bean·핸들러·리스너 미사용 오탐 제거 | 완료 (Java·Kotlin 테스트 통과, DMG 번들 확인). 실제 프로젝트 화면 확인은 남음 |
| S2 | phantom-spring-boot: `application.yml`/`.properties` 키 자동 완성 (spring-configuration-metadata.json) | 완료 (키·값 완성, 빠른 문서. 테스트 12개와 실제 Boot 3.4.5 jar로 확인) |
| S3 | phantom-jpa: `@Query` 안 JPQL 하이라이트와 엔티티 이름 참조 | 완료 (const val·템플릿 포함 주입, 엔티티·속성 이동과 완성, 미해결 이름 오류. 테스트 9개, 사용자 쿼리 20개에서 오탐 0) |
| S4 | phantom-http: `.http` 파일 하이라이트와 실행, 응답 보기 | 완료 (변수·env 파일·Run 거터·응답 창. 핸들러 스크립트, 히스토리, Spring 연동은 남음. 테스트 10개, 로컬 서버로 실행 확인) |
| S5 | phantom-db: 데이터 소스 하나 연결, SQL 콘솔 실행 | 완료 (MySQL·MariaDB·PostgreSQL·H2, 드라이버는 프로젝트 라이브러리·Gradle/Maven 캐시에서 찾음, Ctrl+Enter 실행, 커뮤니티 그리드 결과, 지연 로드 스키마 트리, 캐시만 쓰는 완성, 읽기 전용·WHERE 없는 UPDATE/DELETE 확인. 테스트 11개(H2), 로컬 MySQL에 읽기 전용으로 연결·조회·취소 확인, 사용자 `.sql` 28개 렉싱 오류 0. 드라이버 다운로드, 결과 편집·내보내기, 주입, Spring 설정 가져오기는 남음) |

S1–S5가 끝나면 각 문서의 나머지 MVP 항목을 순위대로 채운다. 각 조각이 끝날 때마다 시작 시간과 메모리를 다시 재서 경량화 원칙을 어기지 않았는지 본다.

## 3. 공통 원칙

모든 문서가 같은 규칙을 따른다.

1. 프로젝트가 그 기술을 쓸 때만 일한다. 확장은 첫 줄에서 라이브러리 존재 여부(캐시된 값)를 보고 빠져나간다.
2. 시작 활동, 상주 코루틴, 프로젝트 전체 무효화를 만들지 않는다. 비싼 탐색은 사용자가 클릭할 때 한다.
3. 플러그인 ID는 `dev.phantom.<name>`, 모듈은 `phantom.<name>.<sub>`로 통일한다 (build-wiring R8).
4. 클린룸: intellij-community API와 공개 스펙만 쓴다.

## 4. UI 원칙: IntelliJ와 비슷하게, 덜 복잡하게

사용자 요청(2026-10-16): "ui는 비슷한데 조금 덜 복잡하면 좋을듯".
IntelliJ의 모양과 조작법은 그대로 두고, 화면에 한꺼번에 보이는 것을 줄인다. 새 시각 스타일은 만들지 않는다.

| 규칙 | 적용 |
|---|---|
| U1 새 툴 윈도우를 만들기 전에 기존 창(Services, Run, Database 하나)을 쓴다 | Docker, Spring 런타임은 Services 창에 노드로 붙인다 |
| U2 탭을 여러 개 늘어놓지 않는다. 한 탭 안에서 보기를 고르는 콤보 하나로 묶는다 | spring-runtime의 Actuator 6개 탭(Beans, Health, Mappings, Env, ConfigProps, Loggers)은 **Actuator 탭 하나 + 보기 선택**으로 바꾸고, ConfigProps는 Env에 합친다 |
| U3 처음 보이는 것은 자주 쓰는 것만 둔다. 나머지는 접힌 영역이나 "더 보기"에 둔다 | HTTP 응답 창은 Body가 기본이고 Headers는 한 줄 요약, Tests와 Log는 접어 둔다 |
| U4 설정 화면은 플러그인마다 한 페이지, 기본값으로 바로 동작하게 한다 | DB 연결 대화상자는 URL·사용자·비밀번호만 기본으로 보이고 드라이버 옵션은 접어 둔다 |
| U5 거터 아이콘은 한 줄에 하나만 둔다. 같은 줄에 여러 개가 겹치면 하나로 합친다 | Spring Bean 거터는 아이콘 하나에서 양방향 목록을 보여 준다 |
| U6 플랫폼 기본 화면에서 Phantom에 없는 기능의 흔적을 지운다 | 빈 툴 윈도우 버튼, 제거한 기능의 메뉴 항목, New Project 마법사의 안 쓰는 생성기 정리 (별도 작업, 측정 작업과 같이 진행) |

각 설계 문서의 UI 항목은 구현할 때 이 표에 맞춰 줄인다. 문서 본문과 다르면 이 표가 우선한다.
